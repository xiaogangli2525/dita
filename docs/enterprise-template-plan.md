# 可替换企业交付模板

状态：设计约定，尚未接入导出。当前 PDF/Word 仍使用 `office-export.js` 和 `pdf-export.js` 中的固定 Letter 版式。本文件约束后续实现，不能作为已支持导入模板的操作说明。

目标是让同一份已按型号过滤的手册，选择不同企业模板后得到不同的交付版式；常规换标识、配色、封面、页眉页脚及水印只需要替换模板包。原始 DITA、型号规则、编辑器皮肤与交付版式各自独立。

## 模板包与文档信息分开

| 层 | 职责 | 更换方式 |
| --- | --- | --- |
| 模板包 | 标识、封面背景、水印、配色、字号、纸张、页边距、页眉页脚及分区策略 | 导入、选择或复制模板；版本独立 |
| 本次交付信息 | 手册名称、型号、版本、发布日期、文档编号、密级 | 在交付面板填写或从项目读取 |
| 手册内容 | 目录、章节、命令、图表、注脚、修订记录、服务及法律说明 | 使用已解析和过滤的 DITA 内容 |
| 格式适配器 | PDF 分页、Word 分节、页码域与媒体表示 | 通过受版本约束的接口注册 |

模板中的字段使用固定白名单，例如 `manual.title`、`manual.model`、`manual.version`、`manual.releaseDate`、`manual.documentId`、`manual.classification`、`company.name`。PDF/Word 当前页及总页数使用适配器的页码字段，不用字符串预先计算。未填写的可选字段隐藏对应行，必填字段缺失在交付检查中列出；不自动用当天日期覆盖发布日期。

企业服务/法律说明继续放在 DITA 主题中，可通过复用机制共享；封面是版式，法律文字是内容，不放入排版代码。

## 模板包草案

一个模板包含 `template.json` 和本地 `assets/`，可以文件夹形式维护并打包导入。以下仅为拟定的数据契约，现有程序不会读取此配置：

```json
{
  "schemaVersion": 1,
  "id": "company-standard",
  "name": "企业标准手册",
  "version": "1.0.0",
  "renderer": "manual-v1",
  "formats": ["pdf", "docx"],
  "company": { "name": "示例公司", "logo": "assets/logo.png" },
  "page": {
    "size": "A4",
    "marginsMm": { "top": 22, "right": 18, "bottom": 20, "left": 22 }
  },
  "typography": { "bodyFont": "Noto Sans CJK SC", "bodySizePt": 10.5 },
  "colors": { "primary": "#166A8F", "accent": "#61B678", "text": "#202B33" },
  "cover": {
    "layout": "brand-panel",
    "background": "assets/cover.png",
    "fields": ["manual.title", "manual.model", "manual.version", "manual.releaseDate"]
  },
  "header": { "right": "company.name", "rule": true },
  "footer": { "left": "page.current", "right": "manual.documentId" },
  "watermark": { "asset": "assets/watermark.png", "opacity": 0.06, "placement": "behind-content" },
  "regions": {
    "cover": { "header": false, "footer": false, "watermark": false },
    "frontMatter": { "header": true, "footer": false, "watermark": true },
    "body": { "header": true, "footer": true, "watermark": true }
  },
  "numbering": { "basis": "physical", "startAt": 1, "displayIn": ["body"] }
}
```

纸张、尺寸、颜色、透明度、资源类型、字段名和布局名都经过校验。模板只声明资源与配置；标题等内容按纯文本处理，不允许执行包内 JavaScript。模板资源使用包内相对路径，不访问网络或任意本地文件。首次支持 PNG/JPEG 标识和背景；矢量图需经过受控转换，字体只使用已安装或有授权的字体。资源缺失、字体不可用、格式不支持某项能力时给出明确检查结果，不静默丢图或退回另一版式。

`schemaVersion` 表示配置协议，`version` 表示该企业模板发布版本，`renderer` 表示布局解释器。三者用途不同。解析后生成完整的规范化配置，不在渲染过程中层层继承并读取可变全局默认值。起步阶段提供“默认简洁”和“企业标准”两套独立模板，不做多级模板继承。

## 存放与替换

应用附带通用模板，用户配置目录保存企业模板包，工作区保存可选的模板选择与交付字段。企业资产不会因使用模板自动进入文档仓库或应用公开仓库；团队可自行通过受控共享目录或私有 Git 仓库分发同一版本。导入时复制为本地受管快照，不依赖同事电脑上的绝对路径。

同一个 `id + version` 对应确定的清单和资源哈希；重复导入相同内容可复用，内容不同则要求发布新版本。文档可绑定模板版本，升级由用户明确选择。删除被引用的模板时提示受影响项目；缺失模板时要求重新选择，不能默默替换交付品牌。

交付界面只展示“模板选择、手册信息、预览”；模板资源管理放在单独窗口，常用字段不要求编辑 JSON。用户可复制模板后修改，预览封面及一页正文，再用于导出。

## 接入现有架构

1. 现有解析、条件过滤与注脚投影先生成交付内容。
2. 模板仓库适配器负责读取、导入和资源检查，纯配置模块负责校验并规范化，不接触编辑器共享状态。
3. 交付捕获同时冻结模板 ID/版本、规范化配置、资源哈希、适配器版本及本次手册字段，与正文快照一起传给检查、预览和导出。
4. PDF/Word 适配器只接收显式快照，不重新读取 DITA，也不重新读取当前模板选择。并发任务分别持有自己的配置。
5. 改变模板、字段或资源使原交付检查失效；交付记录保存上述版本与哈希。若需重新生成完全相同的交付物，还必须保留原内容/模板资产及固定的字体、渲染器环境，不能只存一个模板名称。

现有 `office-export.js` 的内容样式与 `pdf-export.js` 的页码/纸张配置应分别移入格式适配器。不要把 `if (template.id === ...)` 散布到交付控制器中。普通品牌变化走数据配置；遇到封面结构完全不同的模板，通过受控的布局注册接口扩展，并声明支持的字段、格式和能力。

PDF 与 Word 共用配置语义，分页通过各自机制实现：PDF 需要封面、前置页和正文的分区及重复页眉/水印；Word 使用分节、首页页眉页脚和页码域。不能只在整份文件外面套一层 CSS 就认为满足全部要求。两种格式按各自实际页面验收，不承诺不同排版引擎下逐页相同。HTML 后续可复用品牌字段和正文样式，Markdown 只输出内容和必要元数据。

## 实施顺序与验收

1. 定义并验证模板配置/资源协议，实现本地模板注册表，保留现有默认导出路径。
2. 接入模板选择、手册字段、快照失效和预览，使用中性示例资产验证可替换性。
3. 先实现 PDF 的 A4 封面、页眉页脚、低透明度水印及分区页码；检查长表格续页、代码换行、注脚、图片与中文字体。
4. 接入 Word 对等字段与分节排版，再验证实际 Office/兼容软件中页码和水印表现。

关键验收是同一份真实手册切换两套模板而不改 DITA；型号过滤结果一致；关闭封面/水印、切换纸张或页码策略可独立生效；缺资源明确报错；模板升级不会改变已捕获的任务或继续使用旧检查。用户提供的企业参考资料只用于本地版式对照，正式资产由用户提供授权素材。
