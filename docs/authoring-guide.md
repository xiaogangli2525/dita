# DITA Lite 功能与操作说明

适用对象：编写、核对和交付通信模组功能手册的人员。本文按当前界面说明操作；后续 AI 执行任务时，配合阅读 [操作约定](assistant-playbook.md)。功能核查结果见 [走查记录](functional-audit.md)。

## 1. 先理解工作对象

| 对象 | 在这里做什么 | 检查方法 |
| --- | --- | --- |
| 仓库、分支 | 选择当前文档库和版本分支 | 看左侧工作区名称、分支和文件路径 |
| Topic（`.dita` / `.xml`） | 编写一节命令、参数说明或示例 | 看当前标签及正文标题 |
| Map（`.ditamap`） | 组织一份功能手册的章节、顺序和层级 | 左侧选择“当前手册”，点击“打开全文” |
| 型号清单 | 维护项目中可选择的型号名 | 打开“项目型号清单”核对并保存 |
| 型号注脚 | 在具体参数或说明处记录差异 | 核对注脚来源和适用范围 |
| 独立导出规则 | 不改原注脚，为注脚片段记录人工确认的范围 | 看“导出型号规则（不改原文）”中的确认状态 |
| 交付文件 | 按功能、型号、条件和格式生成客户文件 | 检查预览、下载文件及交付记录 |

每个型号仍按 HTTP、TCP、MQTT、资源综述等功能分别交付。一个 Map 通常对应一份功能手册，无需把不同功能或型号合成一本。

**三种内容状态**：编辑区是当前修改；“保存”写入当前工作区；Git 提交/推送再把磁盘修改纳入版本管理。应用目前不提供 Git 提交、推送或 PR 按钮。导出会包含当前编辑区未保存内容，因此导出成功不表示源文件已保存。

界面外观可从右侧工具栏底部 **外观** 或 **查看 → 界面外观** 打开。提供青绿、经典蓝、暖纸、深色四套皮肤，以及自动切换青绿/深色的“跟随系统”。标题旁显示当前实际生效的风格；跟随系统时也会标出青绿或深色。点击卡片立即生效，关闭窗口后继续原位置编写；当前文档、未保存内容和撤销历史不受影响。选择仅保存在当前浏览器，刷新后恢复；浏览器禁止存储时仍可切换，本次关闭页面后恢复默认。外观覆盖工作区、正文、代码、表格和弹窗，不改变客户交付文件的版式。

## 2. 启动与加载文档库

本地服务需要 Node.js 20+、Git 和对文档目录的写权限。在项目目录运行 `npm ci --ignore-scripts`。开发检查使用 Node 20.19+ / 22.13+ / 24+。

Windows PowerShell 示例：

```powershell
$env:DOCS_ROOT = 'E:\work\dita\repo_http'
$env:REPOSITORIES_ROOT = 'E:\work\dita'
npm start
```

macOS/Linux 示例：

```sh
DOCS_ROOT=/work/dita/repo_http REPOSITORIES_ROOT=/work/dita npm start
```

打开 `http://127.0.0.1:5050`。`DOCS_ROOT` 是当前文档库，`REPOSITORIES_ROOT` 是允许切换/克隆文档库的父目录。需要预览练习时运行 `npm run dev`，它复制仓库内真实 HTTP 手册的依赖到临时目录，停止服务后删除该临时副本。

加载远程库：

1. 在左侧工作区设置点击“加载远程库”。
2. 填 HTTPS/SSH Git 地址和新的本地目录名，按需要读取并选择远程分支。
3. 点击“克隆并选择手册”，再选择需要的 `.ditamap`。
4. 核对当前仓库、分支、手册与路径后开始编写。

私有库使用服务运行机器已有的 Git 凭据/SSH 配置。地址中不能带密码、令牌或查询参数；子模块和 Git LFS 不会自动下载。静态演示的远程 Git 控件不可用。

“远程更新”先检查；“拉取更新”只允许已检查提交的快进更新。未保存内容、磁盘 Git 修改、未跟踪文件或分叉历史会阻止更新。先保存、核对并在外部 Git 工具中提交/暂存处理，再重新检查；不要把清理文件作为绕过提示的手段。

## 3. 界面与模式

| 入口 | 操作与用途 | 范围/限制 |
| --- | --- | --- |
| 编写 | 直接编辑结构化正文、段落、列表、表格、注脚 | 复杂结构、复用内容和修订标记会限制直接编辑 |
| 阅读 | 浏览与正文查找 | 只读，不能替换 |
| 源码 | 修改 XML、属性和受保护的复杂结构 | XML 语法检查不等于完整 DITA DTD 校验 |
| 文档 / 当前手册 | 选择 Map、点击章节或“打开全文” | 选择手册改变目录范围；点击“打开全文”才打开其正文 |
| 大纲 | 定位当前打开文档的标题 | Map 中包含当前已渲染的章节 |
| 文件查找 | 按路径查找文件；按当前手册/整个仓库查正文 | 与 Ctrl+F 的当前 Topic 正文查找不同 |
| 属性 | 内容设置、表格命令、高级 XML 属性 | 高级属性修改的是选中元素的源码属性 |
| 注脚 | 查看、定位、编辑、筛选型号注脚 | 适用型号筛选是查看范围，不会自动修改源文档 |
| 审阅 | 比较 Git 基线与当前内容，或处理导入的 Oxygen 修订 | 接受/拒绝后还需保存；接受 Git 差异不等于提交 Git |

桌面可拖动左侧导航边缘或右侧面板边缘调宽；聚焦分隔条后可用方向键调整。窄屏使用“文档”和右侧工具按钮开关面板。帮助菜单的“快捷键”列出当前快捷键。

## 4. 编写和修改正文

1. 点击章节打开 Topic，或在 Map 全文中找到对应章节。
2. 切到“编写”，在普通正文中输入。选中同一段落/单元格中的文字，使用粗体、斜体或行内代码。
3. 把光标放到正文位置后，用顶部工具或 `Alt+Z` 快捷工具插入段落、列表、说明、代码等内容。
4. 用撤销/重做核对修改；观察标签的待保存标记，再保存。

连续输入按输入组撤销；移动光标、命令操作或保存会切断分组。中文输入复用组合输入历史，但不同操作系统的实体输入法仍需现场验收。

Enter 拆分段落、继续列表；空列表项 Enter 可退出列表。代码块保留换行和缩进。Tab/Shift+Tab 用于列表层级、代码缩进、表格单元格导航；先 Esc 再 Tab 可离开编辑区。

粘贴基本富文本可转换段落、粗斜体、列表、链接和规则表格；复杂表格会提示并按纯文本处理。图片使用图片插入工具。注脚、复用内容、修订/批注标记或条件不同的跨段落选区可能被拒绝，缩小选区或使用对应工具。跨过批注标记或特殊文本结构无法可靠映射时，按提示在源码中修改；普通文字的小范围修改会保留原标记位置。

### 修改手册标题

在 Map 全文上方直接编辑手册标题。普通 Map 修改 `title`；Bookmap 修改已有 `booktitle/mainbooktitle` 或其简化标题。标题输入和标题撤销保留其余章节位置，并保留标题之外的源码排版。含行内标记、内容引用或修订指令的标题会显示源码编辑提示，需在“源码”中处理。

### 查找与替换

在“编写/阅读”按 Ctrl/Cmd+F 或 Ctrl/Cmd+H，填写正文文字；Map 中先选择明确的 Topic。匹配可跨粗体等行内标记，但排除注脚、复用和修订内容。阅读模式只允许查找。超过 2,000 处匹配时缩小查询后再全部替换。

在“源码”中，同一入口查找 XML 字符串，可能匹配属性和标签，替换后检查 XML。跨文件定位用左侧“文件查找”的正文搜索；点击结果可定位正文或查看来源，使用“返回编写位置”回到之前的位置。

### 表格、图片、链接和属性

- 表格：在单元格中放置光标，打开属性或快捷工具，插入/删除行列、设置表头或列宽。简单 CALS 表格支持 `1*`、`2*`、`30mm` 等宽度；合并或不规则表格的部分结构命令会禁用。删除整表前核对选中对象。
- 图片/链接：从正文位置插入，选择本地资源或目标；双击已有图片/链接可编辑。新图片可上传到允许的已有目录，也可选择库中已有图片。资源路径相对于 Topic；跨目录另存为会调整受支持的本地引用。
- 高级属性：先选中元素，再展开属性面板中的高级属性。`id`、`product`、`outputclass` 等作用于该元素的 XML；修改 `product` 可能改变适用范围。它不是单纯的外观设置。

## 5. 新建文档并加入手册

1. 点击左侧“＋”或文件菜单“新建文档”。
2. 选择功能概述、AT 命令说明、参数表、操作示例、型号差异或标准 DITA 模板。
3. 填写标题、仓库内的相对路径；父目录须已存在，Topic 使用 `.dita`/`.xml`，目录使用 `.ditamap`。
4. 点击“创建并编写”。这是立即创建工作区文件，不是只建立一个未保存标签。提交期间表单锁定；失败后内容保留，可修改或重试。已存在文件不会被新建操作覆盖。
5. 在左侧选择功能手册和目标节点，展开“目录结构工具”，用“加引用”加入新 Topic。输入路径相对于该 Map 所在目录。
6. 核对章节位置，再保存 Map。新建 Topic 不会自动加入任何已有手册。

上移/下移调整顺序，升级/降级调整层级，“加分组”创建目录分组。“删除”移除 Map 节点/引用，不删除对应 Topic 文件。目录操作可以撤销，保存 Map 后才写回目录结构。

## 6. 型号清单与注脚适用范围

项目设置可从 `product` 标记及明确的适用型号表发现候选。表格中的系列名称可能不是完整子型号；`tbd` 是待定标记，不作为型号。逐项核对型号拼写后保存清单；这只维护可选项，不会自动把注脚分配给型号。

### 新增、编辑和复用注脚

1. 在“编写”的普通正文、列表或表格文字后放好光标；有选区时插在选区之后。
2. 点击“＋ 新增注脚”，或按 Ctrl/Cmd+Alt+N。
3. 填写说明，选择“指定型号”“已确认通用”或“待确认”。指定型号可多选；补充型号用空格分隔。
4. 核对继承条件及来源，再插入。确认编号、正文位置和内容，保存对应 Topic/手册。
5. 已有注脚可双击标记编辑；单击/聚焦标记可查看详情。复杂内容可从注脚窗口导航源码，避免用纯文本覆盖其结构。

型号注脚列表先显示注脚内容、适用范围和操作。点卡片下方的「命令上下文与来源」可查看所在命令、来源和使用次数。长注脚也可在这里展开全文。

“未填写型号”不能自动理解为“已确认通用”。祖先元素的型号条件仍生效：下层注脚不能扩大祖先允许的范围。快捷工具中的“引用已有注脚”从当前手册依赖及明确的资源条目选择公共定义；修改公共来源可能影响多个引用，应查看来源和使用位置。

编号根据当前手册内首次使用顺序展示；多个引用可以使用同一个定义编号。按型号过滤后会重新连续编号。不要为避免显示编号重复而批量改写原始 `id`。

### 原注脚混有多种型号，如何交付

例如原注脚同时包含 `ML307G：范围 1～120。ML307N：范围 0～120。`，仅选择型号不一定能判断全部文字适用范围。

| 机制 | 解决什么问题 | 如何核对 |
| --- | --- | --- |
| XML 的 `product` 等条件 | 过滤有明确结构标记的内容 | 在属性/源码中确认标记及继承范围 |
| “按‘型号：说明’筛选注脚” | 处理符合明确型号前缀约定的旧注脚文字 | 主动勾选，预览该型号保留的说明和标签 |
| 独立导出规则 | 对复杂注脚逐片段人工确认范围，保持原 DITA | 每段选择通用/指定型号，确认并保存规则，再预览 |
| 正文条件过滤（DITAVAL） | 按条件文件保留/排除有标记的正文 | 核对界面的中文规则解释；它不会理解自然语言 |

在注脚面板点击“导出型号规则（不改原文）”，选择注脚，逐片段核对。“填入型号建议”只提供候选；“确认整条通用”需要确实适用于所有目标型号。填写每段范围后，用“筛选预览”检查，再“确认并保存规则”。每次保存针对当前一条注脚；其他注脚的未保存选择不会自动保存。

“显示范围”可筛选待确认、已过期或已确认注脚，顶部显示已确认数量。点击“保存并下一条”，成功保存当前规则后进入筛选范围内的下一条待确认或已过期注脚。保存失败时保留当前条目和填写结果。切换筛选会暂存本窗口内的未保存选择，切回该条注脚可继续核对。

规则写入仓库的 `.dita-note-rules.json`；型号清单写入 `.dita-project.json`。它们是需要版本管理的配置文件。原文或上下文变化后，旧规则可能过期，需重新确认。含糊的技术适用性仍由测试/研发核实。

## 7. 保存、下载、另存为和草稿

| 操作 | 实际结果 | 完成后检查 |
| --- | --- | --- |
| 保存 Topic | 写当前文件；保留声明编码 | 状态提示成功，标签待保存标记消失 |
| 保存 Map 全文 | 显示当前解析手册范围中的已修改文档列表 | 核对勾选范围；未勾选的文件仍待保存 |
| 文件菜单“下载” | 下载当前 XML 的 UTF-8 副本 | 浏览器下载记录；不改变仓库文件 |
| 另存为 | 在仓库内创建/确认覆盖目标副本 | 核对新路径、资源引用和原文件仍在 |
| 草稿/恢复草稿 | 从当前浏览器、仓库与分支的备份恢复到编辑区 | 比较后保存；恢复本身可撤销 |

多个文件保存不是一个跨文件原子事务；若中途失败，状态会说明已保存数量，其余仍待处理。保存期间产生的后续编辑应仍显示为待保存。

草稿和交付历史存在当前浏览器；换设备、换浏览器、清理站点数据或隐私模式都可能使记录不可用。恢复时若磁盘基线已改变，先下载草稿再比较合并。保存冲突时先下载当前编辑副本，核对外部修改后再打开，不要直接覆盖。

出现 `EPERM`/权限错误，核对目录和文件写权限、文件锁、只读状态和安全软件限制；保留当前编辑内容，权限处理后重试。应用不能绕过操作系统权限。

## 8. 审阅变更

1. 打开目标 Topic 或 Map，点击“审阅”。正文保留在中间，变更列表在右侧。
2. 正文在原位置用红色删除线显示删除内容，用绿色底纹与下划线显示新增内容；删除的整段或表格行也保留供核对。点击右侧变更可定位，按块接受/拒绝。标记只用于审阅，不进入 DITA、保存文件或交付文件。
3. 批量操作前检查“全部操作范围”：Git 工作区变更与 Oxygen 修订标记分别处理。
4. 核对正文和 XML，再保存。可使用共享撤销历史恢复误操作。

Git 审阅比较已加载的 Git 基线与当前编辑内容；拒绝差异会改变编辑内容，接受差异不会创建 Git 提交。Oxygen 范围处理已有修订标记，不代表所有编辑都会生成 Oxygen 跟踪记录。Map 批量审阅针对当前已加载手册范围，应等待全文完成加载。

待审阅标记保留至接受或拒绝，保存与审阅决定分别生效。接受该块后清除标记，拒绝则恢复原文，撤销审阅决定会恢复标记。审阅进度保存在当前浏览器，按仓库、分支、文档和 Git 基线隔离。保存文档后刷新页面，或在单篇主题与整本手册间切换，可继续审阅。再次修改已接受的部分会重新显示待审标记，其它未变的已接受块继续保留决定。浏览器存储不可用时，审阅区会提示进度暂时仅保存在本页。Git 提交仍通过外部 Git 工具完成。

## 9. 按型号交付手册

1. 打开目标功能手册 Map，核对当前仓库、分支与全文标题。交付窗口的“交付范围”可选择单篇主题或当前所选的整本功能手册。不属于所选手册的独立主题默认交付该主题及依赖。切换范围会重新读取内容并更新检查结果，请核对范围和型号后交付。
2. 点击“交付手册 ↗”，核对范围和来源摘要。
3. 选择型号、正文条件文件、格式、版本；按原文情况启用明确型号前缀策略，或先核对独立规则。
4. 点击“发布前检查”，处理缺失引用、图片、未确认适用范围或过期规则。检查会列出影响所选型号的注脚及原文位置。可按明确前缀处理的注脚，可直接启用筛选并重新检查。需逐段确认的注脚，可定位原文或打开对应独立规则，返回时会按原交付配置重新检查。
5. “交付预览”检查目标型号的说明、命令、表格、代码块、注脚末尾和回链。
6. 点击“导出文件”，到浏览器下载记录查看并打开实际文件。浏览器决定保存目录，通常为下载目录；若启用了“每次询问保存位置”，按浏览器提示选择。
7. 核对实际文件，查看交付记录。需要追溯时下载记录，保存源文件并在外部 Git 工具中提交源文档和相关配置。

改变型号、过滤条件、格式、版本或源内容后，先前的检查结果会失效，需要重新检查。源文件可以保持未保存状态参与导出；正式交付前建议先保存并固定 Git 版本，便于复现。

| 格式 | 用途与实际行为 | 已知边界 |
| --- | --- | --- |
| HTML | 推荐阅读交付，单文件包含本地图片、目录、注脚和回链 | 用实际导出文件核对浏览器显示 |
| Markdown | 文本化流转与后续处理，包含本地图片数据 | 复杂 DITA 排版不能完全等同 Word/HTML |
| PDF | 本地服务生成可搜索 PDF；预览与下载使用相同字节 | 需要本机 Chromium 和覆盖实际汉字的字体；静态演示使用打印另存 |
| Word | 下载可编辑 `.docx`，保留常用表格、图片和注脚链接 | 网页预览是内容预览，最终分页取决于 Word 和字体 |

本地 PDF 首次运行 `npx playwright-core install chromium`，或设置 `DITA_CHROMIUM_EXECUTABLE`；Linux 安装 fontconfig 和中文字体，用 `npm run check:pdf` 检查。PDF/Word 当前采用 Letter 页面，企业模板和自选纸张尚未实现。静态演示打印另存 PDF 无法确认实际保存，不建立真实文件交付记录。

## 10. 常见卡点与功能边界

| 现象 | 处理方法 |
| --- | --- |
| 找到型号清单，但注脚仍待确认 | 清单只提供候选；为注脚或片段明确选择适用范围 |
| 导出仍出现其他型号文字 | 分别核对结构标记、前缀策略和独立规则；普通正文中的型号说明也需人工检查 |
| 命令/结构工具灰色 | 切回编写；选择有效元素/Map 节点；复杂表格命令禁用时使用源码 |
| 新建文档未显示在手册 | 创建文件之后还需加入 Map 引用并保存 Map |
| 新建后提示刷新或打开失败 | 文件可能已经创建；先核对目标路径，再打开已有文件，避免重复新建 |
| Map 保存失败但 Topic 修改保留 | 看具体文件/错误；先备份，解决引用/权限/冲突后按范围重试 |
| 无法拉取远程库 | 先核对本机 Git 认证、脏文件、本地领先/分叉和远端检查是否已过期 |
| 无法恢复草稿 | 基线或当前编辑已变；下载草稿比较；不要清空存储来尝试修复 |
| AI 写作入口在哪里 | 点击右侧“AI 写作”，直接粘贴问题并继续对话，详细步骤见下方 AI 辅助写作 |

本系统实现常用 DITA 子集：不是完整 Oxygen 替代品，不会加载外部 DTD/实体，也不承诺支持任意 keyref、专业化、复杂条件或复用方式。先用真实库检查引用、表格和所有型号的交付结果；支持范围见 [DITA 兼容性](publication-compatibility.md)。

## 11. 常用快捷键

Mac 用 Cmd 代替 Ctrl、Option 代替 Alt；模态窗口打开时先完成或取消该窗口。

| 操作 | 快捷键 |
| --- | --- |
| 保存当前范围 | Ctrl/Cmd+S |
| 撤销 / 重做 | Ctrl/Cmd+Z / Ctrl/Cmd+Y 或 Ctrl/Cmd+Shift+Z |
| 当前 Topic 正文/源码查找 | Ctrl/Cmd+F 或 Ctrl/Cmd+H |
| 粗体 / 斜体 | Ctrl/Cmd+B / Ctrl/Cmd+I |
| 唤出或收起正文快捷工具 | Alt+Z |
| 新增注脚 | Ctrl/Cmd+Alt+N |
| 注脚窗口应用/插入 | Ctrl/Cmd+Enter |
| 关闭快捷工具/窗口 | Esc |
| 离开正文编辑区 | Esc，然后 Tab |

## 12. 一次推荐的交付练习

用 `npm run dev` 的 HTTP 副本练习：打开全文 → 找到一个 AT 命令 → 改一处说明 → 新增一条目标型号注脚 → 撤销/重做 → 保存并重新打开 → 选择目标型号和待定内容过滤 → 发布前检查 → 预览并下载 HTML → 核对注脚中是否只保留应有差异。

正式操作时，把这套检查用于实际选定的功能库；技术参数与型号适用性由测试/研发确认。代码自动回归和一次 HTTP 库验证不代表其他所有手册都已验收。


## AI 辅助写作

唤出右侧 **AI 写作** 后直接聊天。默认结合当前选区或章节内容，不需要先填需求表或手动定位段落。可以先让 AI 给修改方案，在同一个输入框补充、纠正，再决定应用。只有 Map 中多个章节同样相关时才需明确章节。

具体修改收在“查看原文与修改对照”中。满意后点“应用修改”或输入“应用这版”“按这个改”，进入编辑区并支持撤销，正常保存才写文件。技术数值、单位、命令、型号或约束变化会单独提示，并显示修改行号与适用条件，需核对真实依据。

模型设置仍在独立窗口，保存连接一次后重启仍可使用。每轮默认加载项目的文字修订规则；规则文件、准确性边界和完整操作见 [AI 辅助写作](ai-editing.md)。

全文扫描会逐批保存进度。停止或刷新后，再打开相同范围的扫描面板可恢复已完成结果，点击“继续剩余批次”或“重试失败批次”。再次修改原文的文件会重新列为待扫描，模型连接、修订规则或手册条件变化时也会重新核对进度。进度保存在当前浏览器，存储不可用时界面会提示本次进度仅在当前页面保留。
