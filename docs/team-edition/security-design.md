# 团队版安全设计

## 身份与会话

- 使用 Argon2id 或经安全评估的同等级密码哈希。
- 密码不明文存储、不写日志；管理员重置后要求用户修改。
- Session Token 使用密码学安全随机数；数据库只存 Token 哈希。
- Cookie 设置 HttpOnly、Secure、SameSite；设置合理空闲和绝对过期时间。
- 登录失败限速，支持管理员禁用账户和撤销全部会话。
- 修改状态的请求执行 CSRF 防护。

## 授权

服务端默认拒绝。角色权限与仓库授权同时检查；不能仅靠前端隐藏按钮。每个请求的用户、仓库和工作区在 RequestContext 中固定，避免异步请求跨用户/工作区串用。

## 文件与 Git

- 工作区根目录由服务端生成，路径执行规范化和 realpath containment。
- 禁止任意 Clone URL；仅允许管理员配置的内网 Git 主机。
- SSH known_hosts 严格校验，不使用 StrictHostKeyChecking=no。
- 私钥放入受限权限的凭证目录或密钥服务，不能暴露给浏览器。
- Git 命令参数化调用，限制环境变量、协议、超时和资源消耗。
- 记录真实 DITA 操作者；若使用 Deploy Key，说明 Git 平台看到的是部署密钥身份。

## AI 与网络

- 仅允许管理员配置的内部模型 endpoint。
- 网络 ACL 限制出站访问；防止任意 URL 造成 SSRF。
- 密钥只存在服务端受保护配置，不回传 UI、不写日志。
- 用户级限流、并发上限、超时、响应大小限制。
- 文档提案经结构校验和用户审核，不允许模型直接任意写盘。

## 审计、备份与运维

记录登录、用户/权限变更、仓库登记、Git 写操作、模板发布、导出和 AI 修改应用。日志不记录密码、Session、Token、私钥、API Key 或整篇文档正文。

备份数据库、工作区未提交内容、公共模板和服务器凭证引用；备份加密并限制读取。定期演练恢复。服务器运行专用低权限账号，Nginx 仅开放部门网络入口，内网 HTTPS 使用公司证书。
