# 个人版到团队版迁移计划

## 分支起点

个人版完成功能回归、真实手册交付检查、PDF/Word 版式验收、AI 真实接口验收（如已配置）和文档更新后，打稳定 Tag。团队版从该 Tag 创建长期分支，不从未稳定开发分支分叉。

## 迁移阶段

1. **基线冻结**：记录 Tag、Node 版本、依赖锁文件、测试结果和模板协议版本。
2. **请求上下文**：新增 RequestContext，把全局当前工作区访问替换为请求级依赖。
3. **身份认证**：SQLite、用户、密码哈希、Session、登录和退出。
4. **资源授权**：角色与仓库授权；默认拒绝；加入审计。
5. **工作区隔离**：WorkspaceManager、独立 Clone、工作区级锁、路径约束。
6. **Git 集成**：GitLab/Gitea 仓库登记、内网主机白名单、凭证提供器和分支策略。
7. **AI/模板管理**：管理员统一配置内部模型、公共模板版本管理、用户级限流。
8. **部署与验收**：Linux/Nginx/systemd、监控、备份恢复和 30–50 人测试。

## 兼容原则

DITA 解析、编辑器、型号注脚、审阅、导出和模板渲染尽量保持共用。用户身份、会话、工作区、授权、数据库与运维只存在于团队版。通用修复通过 PR/cherry-pick 同步，不把团队版服务端状态模型倒灌到个人版。
