# 离线知识库发布

入口为顶部 **知识库 ↗**，或 **文件 → 发布知识库**。交付文件为 ZIP，解压后双击 `docs/index.html`，无需安装 Node 或启动服务器。

## 多仓库统一发布

1. 各功能库先加载到本机：已有本地库放在配置的仓库目录；远程库先通过工作台“加载远程库”克隆。批量发布读取本地来源，不自动 fetch/pull。
2. 打开“知识库”，填写统一的型号、SDK 版本和知识库名称。
3. 点击“添加文档库手册”，选择 HTTP、TCP、MQTT 等不同仓库。切换后会自动显示该库的手册入口和正文条件文件。在磁盘上新增入口或读取失败后，可点“重新读取来源”。每份手册独立选择入口、读取方式、正文 DITAVAL、注脚前缀策略、文档版本和模块，然后“加入发布方案”。重复此步配置所有功能库，无需切换正在编辑的仓库。
4. 点击“核对全部来源”。系统依次读取并渲染各手册，逐项显示进度和错误，最后再次检查来源是否变化。
5. 失败项会拦住导出。点卡片“编辑来源”处理配置，或在原库处理保存/规则问题后点“重试未完成项”；通过项保留。也可只点某张卡片“重新核对”。取消会丢弃本轮未封存的结果，迟到响应不能恢复可下载状态。
6. 全部就绪后预览、导出一个离线 ZIP。统一阅读入口和跨手册搜索，功能手册仍各自独立；源库结构与原始 DITA 不改动。

“当前库快速加入”可一次添加采用相同发布设置的手册。已配置的手册若使用不同的过滤条件、版本或模块，请用“核对全部来源”沿用各自设置。第一份来源加入方案后固定型号，更换型号先清空集合。同一仓库的同一入口在方案中保留一个版本。重复添加会提示编辑已有卡片。已指定 Git 版本的入口不能被“当前库快速加入”覆盖；需要改变读取方式时，通过卡片“编辑来源”明确修改。

知识库发布暂时跳过公共库中的《服务与支持》（中文和英文对应主题）。该主题不出现在阅读页、章节目录和搜索条目中，缺少该文件也可继续发布。已有方案中该主题的检索属性会保留配置，但不阻止本次发布。普通手册导出仍保留这一章。公共库的技术章节、声明和图片继续按实际引用加载。

### 两种读取方式

- **已保存文件**：读取该仓库当前分支的磁盘内容，可以包含已保存但尚未提交的修改。方案记录的分支必须仍与实际分支一致；不一致时明确报错。当前编辑器中与这份手册有关的未保存内容会阻止核对；已使用的 Git 忽略文件也会标为未提交内容。
- **指定 Git 版本**：填写本地分支、标签或提交 SHA，也可选完整的 `refs/heads/...` / `refs/tags/...`。直接读取对应提交对象，不 checkout、不 stash、不覆盖工作目录。此方式不包含未提交修改；来源清单记录实际提交 SHA。命名引用核对期间发生变化会要求重试。已初始化的直接 Git 子模块可按父库锁定的提交读取；“已保存文件”模式读取其本机内容。缺少子模块或指定提交时会提示补齐本地来源。LFS 指针、符号链接和下一级子模块仍不自动展开。

每份来源沿用自己的型号清单、独立注脚规则、DITAVAL、编码和图片。后台只接受配置目录内的独立 Git 库及当前库，不接受任意目录。XML/依赖、项目配置、注脚规则和图片都参与来源核对；缺失或变化会报错。每份来源最多 256 个文件、48 MiB 原始数据，单文件不超过 20 MiB；全文发布依赖另沿用 128 文件/8 MiB 文本限制。

### 保存和迁移方案

**发布方案可保存，正文快照不跨刷新保存。** “保存方案”保存统一型号/SDK 和每份手册的仓库、分支或 Git 版本、入口、条件、版本和检索属性。下次打开恢复最近方案，点击“核对全部来源”即可统一重建，不需要逐库切换。已封存内容不会随之后的编辑自动更新；发布前按需重新核对。

- 最多保存 20 份方案，以知识库名称和 SDK 版本区分；选择后点击“加载方案”。“另存新方案”保留当前集合，随后保存为独立配置。加载/导入会替换当前集合，先保存需保留的配置。
- “迁移配置”支持导入、导出方案 JSON，不包含正文、图片或密钥。导入后不会立即读取目录；通过“编辑来源”将每份手册关联到本机已加载的仓库，再批量核对。
- 卡片“核对来源/重新核对”直接读取指定仓库；“编辑来源”修改该份配置，不切换编辑器工作区。迁移到新的本机目录时保留原入口和条件文件。路径缺失时会提示选择替代项。
- 同一方案在其它窗口更新时拒绝覆盖，可重新加载或另存。本地存储不可用时会显示错误，仍可导出 JSON。当前不自动拉取远程仓库；来源核对仍覆盖全部输入，向量可按手册复用，暂不提供片段级增量编码。

## 检索属性

集合卡片“检索属性”可逐章设置使用指南/接口参考/示例/说明，补充搜索别名，以及确认该章正式定义的 AT 命令或 API。只修改发布配置，不改 DITA。符号从已过滤正文提取；正式定义优先于示例调用，未确认定义时仍可查看出现位置。

这些配置绑定章节路径与发布文本指纹。重新加入后原文变化、章节被移除或定义符号不再存在，会标为过期并阻止发布。核对后应用新属性，或清除旧配置再继续；保存方案可保留调整。

## 型号与正文边界

- 复用现有手册发布的项目型号、注脚独立规则、明确前缀和 DITAVAL 策略；原始 DITA 不变。
- 型号选择主要筛选注脚，正文由 DITAVAL 控制。知识库额外拦截发布后仍有明确其它型号 `product` 标记的正文，要求核对条件文件。
- 没有标记范围的正文无法自动判断是否通用；含 Oxygen 修订或未确认范围的注脚会在集合卡片提示，需要发布者核对。
- 页面、章节条目与全文索引均从同一份发布 HTML 生成；被过滤的正文和注脚不会进入搜索数据。

## 客户侧使用

- 首页按功能显示手册，左侧展开章节目录；顶部全文搜索支持 Ctrl/Cmd+K。
- 支持完整 AT 命令、参数名、数字错误码和中文关键词。正式定义优先于示例提及；命令、下划线参数和数字保持完整匹配，支持接口前缀搜索、中文分词、通信领域查询扩展、错别字容错和字段加权相关性排序。
- 可以限定手册、AT/OpenCPU 开发方式和功能模块。输入时显示当前范围的补全建议，方向键选择、Enter 搜索、Esc 收起。结果显示来源、匹配原因和命中摘要，点击定位章节并高亮关键词；“返回搜索结果”继续核对其它结果。
- “命令 / API 索引”列出当前范围的符号，可按前缀筛选并定位正式定义或出现位置。
- 代码可复制，图片已内嵌；相对锚点与注脚返回链接在离线环境工作。不同手册的同名 ID 不会相互覆盖。

首版以 Topic 章节为检索条目，保留完整上下文和所引用的注脚，不按固定字数切片。检索引擎 1.2.2 在原有精确命令/数字匹配和倒排索引上，增加通信领域词典、查询同义表达归一、单词编辑距离容错，以及按标题/别名/符号/正文分字段的 BM25 风格排序；模糊命中会在结果原因和命中词中标明。检索仍是确定性本地算法，不在每次查询时调用 AI，也不需要 Embedding 模型或网络。精确 AT/API 符号命中仍优先于模糊结果。错误码问题中的数字必须在候选章节中精确出现，未收录的错误码返回零结果。引脚章节增加 GPIO、引脚、分配的检索别名；关闭或释放 HTTP 实例定位删除实例，停止传输定位保留实例的终止命令。

检索基准使用 `ML307G-SDK-Preview-Knowledge.zip` 的 2 份手册、26 个章节标题和短文本摘录，覆盖 20 条 HTTP/HTTPS 口语化、同义表达、命令错字和精确命令查询。本轮也直接读取该真实 ZIP 验证 20 条查询，预期章节均排在首位。另以用户提供的 `MR380R-SDK-v1-knowledge-base.zip`（4 份手册、64 个章节）验证 13 条引脚、固件、内存、日志、WebUI 等问题，预期章节均排在首位，并验证未收录错误码返回零结果。回归测试另外覆盖带符号/十六进制错误码、范围筛选、跨知识库读取和 ZIP 解压限制。基准集随实际问题持续扩充，用户问题的召回效果仍取决于手册内容和查询表达。未命中时可使用完整命令或更短关键词。

## 命令行检索

在项目根目录安装 Node.js 20+ 后，先运行 `npm ci` 安装依赖，再用 `npm link` 注册本机命令；也可以直接运行 `node bin/blink-cli.js`。之后可查询离线知识库：

```bash
npm ci
npm link
blink-cli --kb ./ML307G-SDK-Preview-Knowledge.zip "HTTP请求头怎么设置"
blink-cli --kb ./ML307G-SDK-Preview-Knowledge.zip "AT+MHTTPREAD" --json
blink-cli --kb ./ML307G-SDK-Preview-Knowledge.zip --list
blink-cli --kb ./ML307G-SDK-Preview-Knowledge.zip --info
blink-cli --kb ./ML307G-SDK-Preview-Knowledge.zip --get "手册ID#章节锚点" --json
```

CLI 可直接读取知识库 ZIP、解压目录、`knowledge.json` 或旧版 `index.html`。知识库位置通过 `--kb <路径>` 指定，也可设置 `BLINK_KB` 环境变量；未指定时会查找当前目录下的 `docs/knowledge.json`、`docs/index.html`；若当前目录只有一个文件名包含 `knowledge` 的 ZIP，也会自动使用它。搜索复用网页端同一检索引擎，不生成答案、不访问网络。AI Agent 可用 `--json` 获取结果，再通过 `--get` 读取命中章节原文和来源。JSON 的 `knowledgeBase.path` 是本次使用的绝对路径，继续读取时将该路径传给 `--kb`。文本结果给出的读取命令已携带该路径，可在 PowerShell、macOS 或 Linux shell 中复制执行。单次 `--kb` 参数只作用于当前命令。

新导出的 ZIP 增加轻量的 `docs/knowledge.json`，只包含章节文本和来源，不重复打包渲染后的完整 HTML 正文或网页编译索引；CLI 首次搜索时按当前检索引擎构建内存索引。旧版 ZIP 没有该文件时，CLI 会从受支持的离线入口 HTML 中读取嵌入的结构化数据，无需为了 CLI 单独重新导出旧包。读取 ZIP 时只解压选定的机器可读文件或旧版入口 HTML；压缩包上限为 64 MiB，选定文件实际解压数据上限为 128 MiB。

## 输出与验收

| 内容 | 路径 |
| --- | --- |
| 单文件离线门户，包含正文、索引、脚本和样式 | `docs/index.html` |
| 独立功能手册 HTML | `docs/manuals/<手册标识>.html` |
| 型号、SDK、各手册版本、Git 状态、来源路径/哈希、过滤策略、指定 Git 版本、图片哈希、开发方式/模块和章节检索属性 | `docs/manifest.json` |
| CLI/AI 机器可读章节和来源 | `docs/knowledge.json`（新版本导出） |
| 使用说明 | `docs/README.txt` |

每包固定一个型号和一个 SDK 版本，不自动切换到新内容。本版上限为 30 份手册、40 MiB 源内容。发布前以压缩前的 UTF-8 字节数核算 64 MiB 上限，含向量、入口页面、单份手册和 ZIP 头。导出时逐文件使用 DEFLATE，压缩后没有收益的文件直接存入 ZIP。界面在下载后显示实际包体积。CLI 生成的语义 JSON 同样在写入前检查 64 MiB 上限。预览仅准备一次不可变的正文、检索索引与 HTML，正式导出复用这些结果，附带向量时不重复渲染或预先生成普通 ZIP。PDF/Word 可使用现有手册交付功能单独生成，不自动加入知识库包。

发布时，检索索引、阅读页生成、向量响应解析与 ZIP 打包在独立 Worker 中完成。窗口显示阶段、手册/片段进度和交付大小；可在准备、核算、生成或打包阶段取消。关闭发布窗口、切换工作区也会取消任务，保留已核对的来源集合，重新导出会建立新的后台任务。预览和下载复用同一份封存内容，修改标题、SDK 或集合配置后重新准备。

附带语义索引时，同一次流式请求先按实际分片和 Float32/Base64 编码核算完整 ZIP 大小，全部手册通过后直接使用已准备的片段生成向量。首次发布每份手册只分片一次；命中缓存可直接核算，不加载模型。临时分片仅属于当前请求，取消或结束后释放，不维护跨请求的分片缓存。每份完成后立即传回 Worker，并释放该手册的临时数据；最终打包仍独立检查实际大小。取消请求会停止后续生成，不写入未完成的手册缓存。

Worker 直接使用消息传递得到的独立快照，避免再次复制整个集合；普通函数调用仍默认复制以保持输入隔离。ZIP 按文件编码并封存 Blob，避免同时保留全部 UTF-8 缓冲；向量校验共用一个字节/浮点缓冲，组合时逐份处理。以上减少临时内存占用，但总耗时仍受检索索引、模型推理和包体大小影响；传入快照的复制、预览页面的 DOM 加载仍有主线程开销。

可执行 `node scripts/benchmark-knowledge-publish.js 1 5` 对比同步发布和生产 Worker：每种模式独立进程，记录耗时、主线程心跳最大间隔、峰值 RSS 和 ZIP 大小。输入为 1/5 MiB 合成正文，并非浏览器或真实文档性能结论。真实 HTTP 手册的浏览器验收另覆盖容量拦截、取消后重试、首次/缓存向量导出和离线阅读。

自动化使用真实 HTTP 库验证知识库保留 24 个 Topic、25 条 ML307G 注脚，普通手册保留 25 个 Topic；另用独立临时库验证同一方案无切换批量捕获、指定分支/标签/提交、失败重试、取消、草稿保留和跨仓库同名路径、正文条件与注脚排除、来源哈希、取消/未保存保护。解压包在中文和空格目录移动后，用 Chromium 的 `file://` 和断网模式验证搜索、阅读、复制和窄屏布局。实际 Windows Edge/Chrome 仍需现场核对。

预览样本由真实 HTTP 手册和其中的 HTTPS 示例组成。合成的隔离测试库不进入提供给用户的样本。


## 离线语义检索验证版

Windows 便携包将 Node 运行程序、CPU 推理库、分词器、约 24 MB 的 BGE 中文量化权重和知识库一起交付。客户解压后，在目录中运行 `.\blink-cli.cmd KB "怎么把日志取出来"`。运行时从本地加载模型，关闭远程模型加载。所有手册共享同一份模型组件。

工作台发布人员先执行 `npm run prepare:semantic` 准备固定版本模型，再启动工作台。发布知识库时勾选“附带离线语义索引”，系统按已过滤的交付正文分片并生成 512 维归一化向量。分片使用随模型提供的实际分词器，标题和正文合计不超过 512 个 Token，保留重叠正文并覆盖章节末尾。标题单独限制预算，编码前核对长度，超限会报错。完整章节与注脚保留在原文中，结果片段可通过 `--get` 返回章节核对。此次网页阅读入口继续提供关键词检索，语义索引供 CLI 使用。

已有 ZIP 可由发布人员生成语义版本，再制作便携包。

```bash
node bin/blink-cli.js --kb ./MR380R-SDK-v1-knowledge-base.zip --build-index ./MR380R-semantic-knowledge.json
npm run build:blink -- ./MR380R-semantic-knowledge.json ./dist/blink-cli-windows-x64.zip ./MR380R-SDK-v1-knowledge-base.zip
```

默认输出为 `dist/blink-cli-windows-x64.zip`。输入本身是完整语义知识库 ZIP 时会自动保留原 HTML；语义 JSON 可通过第三参数传入原知识库 ZIP，构建时校验型号、SDK 版本及各章节正文一致后复制 HTML。构建过程需要网络安装固定版本运行依赖、下载并校验 Windows Node；用户使用已构建的包时从本地加载资源。包中包含模型与运行库的许可说明。量化权重的 24 MB 不包含运行库和知识库，最终包体积应以生成的 ZIP 为准。

ONNX Runtime 1.21.0 的第三方许可通知原件随仓库保存在 `docs/licenses/`，随包复制到 `runtime/licenses/`。构建会校验包内通知文件的 SHA-256 和已安装的运行库版本。[ONNX Runtime 1.21.0 通知原件](https://sources.debian.org/data/main/o/onnxruntime/1.21.0%2Bdfsg-1/ThirdPartyNotices.txt)

不同功能的手册可分别生成语义 JSON，再通过重复的 `--merge` 组合查询。合并要求产品型号、SDK 版本和完整 Embedding 配置一致，拒绝重复手册 ID。兼容向量直接复用，保留每份手册的独立 Git 来源。

```bash
blink-cli --kb ./http-semantic.json --merge ./webui-semantic.json "请求参数怎么配置" --json
blink-cli --kb ./http-semantic.json --merge ./webui-semantic.json --build-index ./sdk-semantic.json
```

CLI 默认为 `--search auto`，带语义索引时启用混合检索。`--search lexical` 可单独使用关键词，`--search semantic` 用于对照验证。完整 AT/API 名称和错误码保留精确约束；明确标题及别名保留排序优先级。自然问句综合关键词与达到最低相似度的语义片段，跨模块的显式协议名参与范围约束。中文未知片段不再通过单字编辑距离凑足命中覆盖率。只在正文提及协议名时，结果会提示读取原文核对使用步骤。

当前默认分片配置为 `bge-small-zh-int8-cls-v3`，使用发布后的结构块。向量输入先做 NFKC 与英文大小写统一，使大写 AT 命令和 API 名称获得正常分词，原始正文、显示内容和关键词精确检索保留原文。文档向量和查询必须使用相同配置。v2 与 v3 使用相同的模型编码，v2 索引仍可查询；更早或不兼容的配置在 `auto` 下提示并回退关键词检索，显式语义检索要求重新生成。不同分片配置的包组合时需统一重建；可直接以旧 JSON 执行 `--build-index 新文件.json`，无需修改 DITA。多包重建也会统一重新编码。

该版本返回检索线索与原文，尚未增加问答生成。轻量模型的语义覆盖仍有漏检，固定相似度阈值也不能证明章节包含完整答案。验收须同时覆盖有答案、仅提及和无相关内容的问题。

便携包根目录提供 `blink-cli.cmd`、`README.txt`、`docs/` 和 `runtime/`。阅读入口位于 `docs/index.html`，独立手册位于 `docs/manuals/`。运行依赖收在 `runtime/app/node_modules/`，模型位于 `runtime/models/`。向量仍保存在 `docs/knowledge.json` 的 `semantic` 字段，`chunks` 对应正文片段，`vectors` 为 Base64 编码的 Float32 小端二进制矩阵，`profile` 记录 512 维模型与编码配置。


## 结构化分片与发布前检查

知识库捕获复用现有型号过滤、DITAVAL、复用引用和注脚规则的发布结果。在章节正文被压平前，从发布 HTML DOM 提取结构块；原始 DITA 不改写。通用提取器同时服务浏览器与 CLI 的旧 HTML 恢复，避免维护两套分片规则。

- 普通段落、列表、定义项、操作步骤、代码与图片说明保留内容边界，代码保留换行和缩进。
- 参数表按完整行或关联单元格提取。还原跨行、跨列与多级表头，为相关行带上列名、继承行内容和表头注脚。全宽参数说明按参数定义分组，取值枚举和示例保留所属参数名与默认值；支持 DITA 定义列表包装以及紧随参数定义的下一表格行。超长参数行在各片段重复行标识。
- 只附带明确引用的注脚，包括合并单元格和表头中的引用。不同型号的正文和注脚仍由发布阶段的策略决定，分片不推断适用型号。
- 手册标题、章节与小节路径、行内容和关联注脚共同计入 512 Token 预算。超长块按行、段落或标点继续拆分，并标记为分段；普通结构块不机械重叠，旧纯文本回退仍保留重叠。
- 必要表头或关联注脚本身超出预算、缺失注脚、非法表格跨度会明确报错。只剩纯文本的历史 JSON 无法完整恢复结构，CLI 会提示回退；含发布 HTML 的旧包可恢复结构，并校验 HTML 与机器可读正文的一致性。

核对手册后，点击发布窗口底部的 **检查检索片段**。选择章节后，左侧显示发布原文，右侧显示实际送入模型的片段、Token 数与关联注脚。点“定位原文”高亮对应元素；可切到“旧版长度分片”比较。预览需要先准备本地模型，与正式导出使用同一套分片实现。

结构块记录内容标识、指纹和发布锚点；片段另带来源路径和父章节。指纹用于缓存失效判断，不是安全签名。向量按手册持久化复用，正文变化会重新生成所在手册；详见下文缓存说明。

CLI 默认生成结构化分片，可显式生成旧版用于对照：

```powershell
node bin/blink-cli.js --kb .\knowledge.zip --build-index .\structured.json
node bin/blink-cli.js --kb .\knowledge.zip --build-index .\legacy.json --chunking legacy
node scripts/check-knowledge-chunks.js .\knowledge.zip http .\comparison.json
```

对照脚本也支持 `mr380r` 问题集，固定问题位于 `tests/fixtures/knowledge-chunk-cases.json`。同一份发布内容、同一模型分别测旧版与结构化分片的纯语义及混合检索，记录首位、前三位与无答案误命中；输出报告使用新文件名。

第一版依赖发布器保留的 HTML 结构，尚未独立实现全部 DITA 特化语义，也不分析图片像素。图片使用已发布的替代文本或说明。片段增加会增大索引并增加首次构建成本；客户侧继续共享同一份模型。默认保留混合检索，纯语义模式用于对照评测。

### 按手册复用离线向量

发布窗口勾选“附带离线语义索引”后，每份手册独立检查本机缓存，再组合为本次交付的 `semantic` 索引。进度显示当前手册和片段，完成后显示复用、重新生成的手册数量及总片段数。“向量复用设置”中的“本次重新生成全部向量”仅影响这一次发布，成功后自动关闭。缓存不可写或损坏时会提示，并继续从当前正文生成交付文件。

复用条件包括交付型号、手册和章节标题、正文、结构块、关联注脚、定位标识、分片配置及固定模型和编码运行库版本。SDK 标签、文档版本、Git 提交、核对时间和检索别名更新本次交付元数据，不会因这些信息变化单独重新计算向量。正文或关联注脚变化时，重新生成其所在整份手册；目前没有片段级增量编码。重排、添加或移除手册会重新组合和校验索引位置，未变的手册继续复用。

CLI 使用相同缓存机制，独立生成的兼容向量包也可直接组合：

```sh
blink-cli --kb ./http.zip --build-index ./http-vectors.json --json
blink-cli --kb ./http.zip --merge ./webui.zip --build-index ./sdk-vectors.json --json
blink-cli --kb ./http-vectors.json --merge ./webui-vectors.json --build-index ./combined.json --json
blink-cli --kb ./http.zip --build-index ./http-rebuilt.json --rebuild
```

`--build-index` 始终写入新文件，不覆盖输入。JSON 结果增加 `reusedManuals`、`rebuiltManuals`、`totalManuals`、`totalChunks` 和 `warnings`。生成需要离线模型；命中缓存或组合完整兼容索引时不加载模型。客户执行语义搜索仍需随便携包提供的模型；本机缓存不加入客户包，也不改变原 HTML 和 DITA 文件。

默认缓存位于 Windows `%LOCALAPPDATA%/dita-lite/knowledge-vectors-v1`，Linux `$XDG_CACHE_HOME/dita-lite/knowledge-vectors-v1`（未设置时为 `~/.cache/dita-lite/knowledge-vectors-v1`）。可用 `DITA_SEMANTIC_CACHE_DIR` 指定位置；删除该目录只影响后续生成速度。缓存含片段正文，应与源手册采用相同访问权限管理。单份缓存上限 64 MiB，总量默认上限 256 MiB、64 份，超限按最近使用情况清理本工具的旧条目。每份文件含完整性校验，通过临时文件原子替换保存；取消不会保存半成品。


### 检索约束与结构块读取

网页、CLI 关键词检索和语义分流共用查询约束解析。完整 AT/API 符号、纯数字（包括负数、小数、十六进制）以及中英文错误码/状态码问题保留关键词精确约束；即使显式选择 `hybrid` 或 `semantic`，也不会用相似章节补回未收录的编号。这类查询不加载模型。领域词典、查询同义词和章节别名规则集中在 `public/knowledge-search-profile.js`，离线网页内嵌同一配置。

语义命中附带 `chunk`，包括 `unitId`、`sourceAnchor`、`sourcePath`、起止偏移、小节路径和关联注脚 ID。结构化章节另含可读取的 `chunk.blockId`；偏移相对于结构块正文，旧纯文本则相对于归一化章节正文。每章仍只返回最高相关片段，保留章节去重；强关键词命中的排序保持优先。

```sh
blink-cli --kb ./knowledge.zip --get '手册ID#章节锚点' --block '结构块ID' --json
blink-cli --kb ./knowledge.zip --json -- -17
```

`--block` 返回整个结构块、必要上下文和关联注脚，长块可能对应多个模型片段；不传该参数仍读取整章。旧纯文本包可继续按章读取，但不能凭文本推测块结构。块 ID 绑定内容，重发包后应从新结果取得，不能跨版本沿用。

取消来源核对或关闭窗口会向目录遍历、文件读取和 Git 子进程传递取消信号。并发槽位在后台任务结束清理后释放，不会继续写出取消结果。分词分片定期让出事件循环以处理取消；已开始的单批模型推理在返回后丢弃结果，不保存半成品缓存。

分块正文、标题前缀和重叠区间按完整 Unicode 字符截断，避免把 emoji 或扩展汉字拆成两个代理码元。旧索引仍可读取；更新后的本机缓存规则为 `manual-index-v2`，第一次生成会重建旧缓存，随后继续按单册内容跨 SDK 版本复用。

后台 Worker 使用 DEFLATE 或 STORE 逐文件打包为 Blob，源快照上限是 40 MiB，ZIP 安全读取上限是 64 MiB，解压数据上限是 128 MiB。压缩只改变 ZIP 的存储方式，解压后的 HTML、清单、图片和 Float32 向量保留原字节。数字与错误码保留精确证据约束，AT/API 查询还支持前缀与拼写纠错。
