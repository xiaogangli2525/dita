# 功能说明与流程走查记录

本轮以 `master@12d6c9f` 为功能基线，结合当前界面、实现和自动回归核对。用途是把可用能力和操作边界整理清楚，为后续 AI 接入提供可执行约定；不是全 DITA 支持或所有运行环境的认证。

文档入口：[功能与操作说明](authoring-guide.md)、[AI / 自动化操作约定](assistant-playbook.md)。源手册采用仓库内用户提供的真实 HTTP/HTTPS 库，测试操作在临时副本中进行。

## 发现及处理

| 项目 | 核对结果 | 处理 |
| --- | --- | --- |
| 操作说明分散 | README 和历史验证记录偏开发视角，缺少当前中文任务流程 | 新增按场景编排的操作说明和 AI 操作约定，README 提供入口 |
| 保存/提交/导出概念 | 保存到磁盘、提交 Git、导出未保存缓冲区容易混淆 | 说明分别写清落点、范围和完成检查；明确应用无 Git 提交/推送 UI |
| 型号识别/适用范围 | 型号清单只是候选；DITAVAL、文本前缀和独立规则解决不同问题 | 分别说明操作和检查方法，不把系列名、tbd 或文字提及当成自动确认 |
| 新建提交期间表单可变 | 延迟请求时，模板、标题、路径和取消按钮仍可操作；浏览器回归在模板禁用断言上复现失败 | 提交期间锁定整份表单、阻止重复提交/取消；失败保留内容并允许重试 |
| 新建请求跨工作区 | 新建控制器缺少表单会话代次；旧错误可能写到重新打开的表单 | 工作区变更时关闭并重置新建会话；异步阶段检查身份，忽略过期成功/失败及清理动作 |
| README 审阅描述 | 仍称并排 diff，与正文居中、右侧变更面板的当前界面不符 | 修正文案，操作说明补充 Git/Oxygen 批量范围与保存语义 |
| 手册服务职责与依赖 | 文件/快照读取与型号校验、注脚索引、发布准备混在一个服务，依赖编辑器的章节遍历 | 拆出无 UI/IO 的 `manual-domain`；共享章节遍历归入 `manual-core`，保留现有服务接口 |
| 快照读取期间设置变化 | 原服务在 IO 完成后读取型号设置，可能混合读取前后的上下文 | IO 前复制/冻结型号设置，读取中与使用前核对工作区、分支、配置内容/错误和型号值；文件记录复制/冻结 |
| Author 与输出模块职责集中 | `app-core` 混合投影、回写、修订和装配；交付转换内含预览及全文样式 | 拆出 XML DOM、Author 渲染/回写、Oxygen、Markdown 预览和 HTML 文档外壳；兼容入口显式转发，依赖方向由 Lint 限制 |
| 带批注标题的编辑 | 真实 HTTP 两个标题带批注；原回写可能把批注标记移到文字末尾 | 基于规范源码范围和最小文字修改保留标记/实体位置；跨标记或无法可靠映射的修改明确拒绝 |
| 普通 CDATA 文本 | 原普通节点渲染只处理 Text，CDATA 可能漏显和漏导出 | Author/HTML/Markdown 按普通惰性文字处理，保留未修改源片段 |

## 本轮结果

2026-11-03 本地结果：

- `npm run lint`：零警告。
- `npm test`：250 项单元/HTTP 检查全部通过，无失败/跳过。
- `npm run test:browser`：212 项 Chromium 检查全部通过，无失败/跳过；本地通过 `DITA_CHROMIUM_EXECUTABLE` 指定 Chromium 153.0.8010.0，安装覆盖实际汉字的本机字体后运行。
- 新建相关定向运行：`document-transitions-browser.test.js` 共 15 项通过，覆盖请求期间字段锁定、重复提交/取消拒绝、失败重试，以及替换工作区后旧失败不能改动新表单。
- 真实 HTTP 全文验证 25 个 Topic；`model-export-browser.test.js` 验证 ML307G、ML307N、MN319-A 的实际 HTML，且共用策略覆盖四种格式。相关测试在临时副本操作，并检查原输入字节保持不变。
- 三份新增 Markdown 说明的相对链接已核对。操作说明依据界面入口与实现核对；不宣称已经验证全部私有库认证、Windows 文件锁或每个物理输入法。
- 规则层新增干净 Node 进程回归：无需编辑器、DOM 或工作区服务即可准备发布与索引注脚。真实 HTTP 数据快照可为三个型号生成一致的注脚筛选结果，保留全部输入。配置替换、原地型号修改、读取错误变化和仓库/分支变化均会使旧捕获失效。
- 文档规则依赖受 Lint 约束；快照集合现由私有 Map 的只读迭代视图提供。关键工作区写入集中在 session 操作，文档与保存回执集中在 document-store；审阅选择和 DOM 临时状态仍由 UI 控制器维护。
- `npm run typecheck`：严格检查真实文档/提案/保存实现、手册快照捕获和交付记录构建；负向类型用例确保错误字段、快照写入和无效格式被拒绝。其余 UI 模块按需逐步纳入。
- Author/输出模块可在不加载应用入口或编辑器服务的情况下独立加载；新增范围解析、修订索引、惰性 CDATA、批注位置、HTML 元数据转义和 Markdown 安全预览检查。真实 HTTP 25 个 Topic 全部通过原样回写及连续标题修改；另测 CRLF、DTD、CDATA、实体、PI 和含 `>` 的属性。
- 与整理前版本对照，公开 `DitaVisualCore` API、六组普通 HTML/Markdown 输出和两种 Markdown 预览结果保持一致。批注编辑及 CDATA 为本轮明确修复，不纳入“所有行为不变”的结论。

## 界面外观

- 四套皮肤：青绿、经典蓝、暖纸、深色；另支持跟随系统。右侧“外观”和“查看 → 界面外观”均可进入，原生单选卡片支持键盘操作。
- 统一工作区、正文、表格、代码、注脚、审阅、弹窗和状态色的语义变量。真实 HTTP 手册检查桌面/小屏布局，四套皮肤的代表性正文、辅助文字、按钮和状态文字对比度达到 4.5:1。
- 进一步按实际灰底/选中背景核对辅助文字，而不是只比较白底色值：修正模式按钮、仓库区、章节小标题、短描述、深色输入提示和搜索当前项的对比度。统一菜单悬停与属性焦点，禁用主按钮不再响应悬停配色；长内容区使用随皮肤变化的细滚动条。外观标题旁显示实际生效的风格，系统模式也会实时更新。
- 验证刷新恢复、系统实时切换、禁用存储的降级、未保存缓冲区/撤销/源码选区与滚动不变、Author 光标恢复；浅色/深色 HTML 完整输出逐字节相同。

## 仍需按使用计划补齐

| 能力/边界 | 当前状态 | 后续建议 |
| --- | --- | --- |
| AI 编写/修改 | 仅有快照绑定、提案校验和应用原语，无模型调用与审核 UI | 依照操作约定接入服务端适配器和可接受/拒绝的修改差异 |
| Excel 测试问题 | 无导入、问题定位和逐行处理面板 | 保留行号/原问题，先定位与人工确认，再生成有限修改提案 |
| DITA 兼容性 | 常用子集；不处理所有专业化、keyref、复杂复用与外部 DTD | 新手册先做引用/表格/条件的导入和交付验收 |
| Word/PDF 版式 | 常用内容可交付；Letter，暂无企业模板和自选纸张 | 收集实际交付模板后再扩展；最终 Word 分页在 Word 中核对 |
| 多浏览器、实体输入法及 Windows 文件权限 | 当前自动化主要覆盖 Linux Chromium；组合输入部分为模拟事件 | 在实际研发 Windows 环境、常用输入法和客户阅读环境进行现场验收 |
| 多型号技术正确性 | 测试检查过滤机制；不会证明每个技术参数的适用型号正确 | 测试与研发核实技术语义，保留待确认项和修改证据 |
| 大型正文性能 | 仍包含整 Topic 转换；合成性能数据是诊断样本 | 根据真实长手册编辑反馈选择优化点 |

“回归通过”表示上述流程在给定测试环境通过，不能解读为零缺陷或所有手册都已验收。新增入口、保存范围或过滤策略时，应同步修改说明和对应场景的回归证据。
