# 按型号随 SDK 交付知识库：后续计划

状态：已记录，暂缓实施。当前优先完成 AI 辅助写作。

## 已确定的方向

- 继续维护原有按功能组织的 DITA/Git 文档库，同一来源生成手册和知识库。
- 交付单元为“型号 + SDK 版本 + 离线文档包”。HTTP、TCP、MQTT、资源综述保持独立，统一入口和跨手册搜索。
- 客户解压 SDK 后双击 `docs/index.html`；目录、搜索、图片、脚本和样式全部离线可用，不依赖安装 Node 或启动服务器。
- 发布时对正文、注脚、搜索索引执行同一套型号过滤，不能只在页面隐藏其他型号内容。
- 记录文档版本、SDK 版本及各仓库提交；旧 SDK 的文档不自动切换到最新内容。文档修订可另发对应版本的补丁包。

## 首版范围与验证

先用真实 HTTP 库生成单型号离线包：入口、目录、全文搜索、命令/参数/错误码精确查找、章节锚点、代码复制和可选 PDF。

验证断网双击、Edge/Chrome、中文和空格路径、解压后移动目录、图片和链接、搜索结果与手册型号一致。`file://` 有加载限制，不能把依赖 fetch/ES modules 的在线站点直接打包宣称可双击使用。生成时间、体积与检索速度用真实内容测量。

## 后续扩展

- 按命令/任务划分条目，保留参数表、前提、注脚以及仓库、路径、Topic ID、原文锚点、型号和版本；避免按固定字数切断上下文。
- 型号/版本是明确的筛选条件，不由语义相似度决定。
- 首版全文搜索；积累真实问题后评估漏检，再考虑关键词与向量混合检索。离线语义查询还需匹配的嵌入模型和运行时，仅打包文档向量不够。
- 先保存 DITA 中已确认的引用/关联记录；出现多层关系分析需求后再评估知识图谱，不先引入图数据库。
- FAQ/排查方法从研发确认的问题积累，不根据缺失的技术事实自动生成答案。
- 客户问答仅基于对应型号、版本的已发布内容，附原文来源；与内部 AI 修订/人工审核流程分开。

这些是后续设计约定，不表示当前已经提供知识库导出或 AI 问答功能。
